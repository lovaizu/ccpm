# README

読み手は、その製品を初めて知った人。読み終えたら、自分に何をしてくれるかが分かり、使うかを決め、使い始められる。

- 冒頭で、何が楽になり、何が起きなくなるかが分かるか。

- 完成した製品を使う体験として書かれているか。

- 使い始めてから結果を得るまでの流れと、各段階で何をして何を得るかが、一目で分かるか。

- 例は、読み手が自分の仕事として思い浮かべられる場面か。

    製品の強みが見えて、読み手自身の仕事に近い場面を選ぶ。たとえば、JavaScript のアプリを TypeScript に移す場面。ほかの会社の製品名や、有名なアプリをまねて作る例は使わない。

- 使う人に見えるものだけで書かれているか。

    内部の役割の名前と、初めて使う人に要らない例外は、設計書に書く。なぜこの形にしたかは、読み手が「なぜ」と思うその文の中で、設計書へリンクする。

- 手に入れて使い始めるまでの手順と、ライセンスがあるか。
