# 要件整理

内部文書。お客様のインプット資料や現行サイトから事実を整理し、見積もれる状態をつくる。**このキット全体の母艦**＝以降の文書はすべてここの要件番号にたどり着く（母艦＆トレースの仕組みはスキルの「たどれるようにする」を参照）。

## インプット台帳
見積の根拠とする資料・現行サイトを全件挙げ、どこまで確認したかを示す。**i→r のリンクはこの台帳に持たせない**＝どのiがどの要件になったかは要件リストの`出自`列だけが持つ（同じリンクを2か所で手入力すると必ずズレる）。まず対象を「インプット一覧」に丸数字（①②…）で箇条書きし、表の`対象`列はその番号で参照する（長い名前を毎行繰り返さない）。現行サイトは1ページ＝1行で網羅し、全件の行は別ファイル `inventory/*.md` に置く（この表はサイト×セクションの集計でよい）。セル内に複数項目が入るときは改行（`<br>`）で見やすくする。

## 母数（件数の正）
> 同じ「ページ」でも数えているものが違う（スキルの母数⚠️）。**別々の母数は別々の欄に**書き、prose に流さない。ここが件数の正で、02・03・04はこの値を引用するだけ（数え直さない）。埋まらない欄は空のままにせず、不明点(q)に上げる。

| 母数 | 件数 | 1件が数えるもの・起点（どこから数えたか） | 出どころ（`inventory/*.md`／数え方） |
|---|--:|---|---|
| 現行ページ数（クロール実数＝移行ボリュームの母数） |  |  |  |
| 移行するページ数（台帳の`移行`＝する の件数） |  |  |  |
| 転送(301)対象URL数 |  |  |  |
| 新サイトのページ数（新IA・ページ一覧から導出） |  |  |  |

> **この4つは別の数**。現行ページ数をそのまま移行工数や新サイトの規模に持ち込まない（統合・アンカーセクションの分割で新サイトは増え、作り直しで移行は減る）。台帳の`移行`＝**作り直し**のページは**移行件数に数えず**、新サイト側の新規制作として数える。
