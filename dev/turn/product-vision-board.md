# Turn Product Vision Board

## Roles

- **user**: one who asks Turn for a work, such as a README, and decides what is theirs.

## OKRs

- O1: The user gets a work they put to use as handed over, having decided only what is theirs.
  - KR1.1: Of the works the user asks for, the share they did not put to use as handed over,
    or for which they were asked a point that was not theirs. Lower is better.
  - KR1.2: The time from the user's request to a work they put to use. Shorter is better.

KR1.1 comes first: a change that improves KR1.2 is kept only if KR1.1 does not get worse. Key
results have no targets, as a measure made a target stops being a good measure (Goodhart's
law). They show whether a change brought its objective closer.

## Product

Turn instead of asking an AI in one prompt, reading its draft and mending it:

- **Made from a best practice**: the user receives a work built toward its reader's purpose by
  the best practice of its kind, not one an AI starting from scratch has mapped from similar
  text (O1).
- **Checked by purpose and intent**: the user is handed no findings off the essence to sort, as
  Turn checks whether the work's reader gets what they need and the user's intent holds, not
  whether the work follows the best practice (O1).
- **Every intent drawn out**: the user's intent is drawn out point by point before the work
  is made, so they do not find guesses in the draft to mend (O1).
- **Checked in use**: the user receives a work that has been tried as its reader would use it, so
  it works in use, not only on reading (O1).
- **Seeks the good**: the user gets a work made good from its root, not patched fault by fault,
  so it carries none of the noise that added fixes bring (O1).
