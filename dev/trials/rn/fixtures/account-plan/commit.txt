I propose to approve the plan and work out the design next: how the name is made from the ID and
the key so no two users share one, what it reads as, what is shown when no ID is passed, where the
key lives, and what the command looks like. Each is a point the plan leaves open, and the design
settles them before anything is built.

Besides the two below, the plan keeps every name that is right today as it is, shows a user with
only a first or a last name by that name alone, moves `src/account` to TypeScript so a mistake of
the kind in `docs/incidents.md` made in it fails the build, and keeps the key out of the
repository.

Toward what you would choose it for (first proposal):
- A1: planned, nothing built yet: a user who signed up with only an email address is shown a code
  such as "User 7F3K2Q", their own, revealing nothing, never "undefined".
- A2: planned, nothing built yet: support turns such a name back into the user's ID with one
  command run with the key.
