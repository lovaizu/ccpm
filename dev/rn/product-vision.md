# Product vision of rn

## Roles

- user\
  One who asks rn for a deliverable, such as a document, code or a plugin, for the people it's for.

## Objectives and key results

- O1: the user gets each deliverable they mean, one that its people can use for what they're after.
  - KR1.1: the share of the deliverables rn hands over that the people they're for couldn't use
    for what they're after. Lower is better.
  - KR1.2: the time from the user's request to the deliverable, the user's own time answering rn
    included. Shorter is better.

KR1.1 comes first: keep a change that improves a key result only if none before it gets
worse.
Key results have no targets, as a measure made a target stops being a good measure, by Goodhart's
law. They show whether a change brought its objective closer.

## Concept

rn works only on the [vital few](https://en.wikipedia.org/wiki/Pareto_principle), what decides
whether a deliverable's people can use it.

- Only the user's decisions asked, for O1\
  rn asks only what the user alone can decide, so they get what they mean without a specification.
- Every deliverable by best practice, for O1\
  rn makes each deliverable by its kind's best practice, so it holds what that work needs.
- Judged by the people it's for, for O1\
  rn judges each deliverable as its people would use it, so it improves only what they need.
