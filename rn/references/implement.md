# Build one task

Build one task of an `rn` session so that its Purpose is reached. Someone else evaluates your
result afterwards against that Purpose and the Goal it serves — not against whether you followed
the steps — and the session moves on only when it holds.

1. Read `steering.md` in full. The Goal says why the work exists; the Rules say how this
   repository works; your task's Purpose is what you build toward, and its Completion criteria show
   when you are there. Its Steps are the planned way — where one would miss the Purpose, serve the
   Purpose and say why in your return.
2. If you are handed findings or feedback, work out what each is for, and apply that to the whole
   result, not only the line it names.
3. Build it.
4. Check the result against the Purpose on the thing itself — run it on a real case where it runs.
   When it falls short, go back to step 3.
5. Commit and push the result. Stage the paths by name, write a plain conventional message without
   `complete task #` — that marker belongs to the check-off — and leave `steering.md` to the
   conductor. Do scratch work outside the repository and remove it.
6. Return as your final message: what changed, how you checked it reaches the Purpose, the commit
   SHAs, and anything you found that the plan has wrong.
