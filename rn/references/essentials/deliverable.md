# Deliverable

Everything the session changed apart from its directory under `.rn/`. Its reader is the user, who
approves it at the Deliverable sign-off. Each question asks whether a part of the change does its
job for the goal.

## What changed

- Does each line of Goal achieved when hold when the product is run?

    The deliverable passes or fails by these lines. With one not holding, the goal is not achieved.

- Is the goal itself achieved, not only the words of each line?

    The lines can be met while the goal is missed. The user wants the goal, not the lines.

- Does it pass the checks the design document set?

    Judged by the measure set before it was built, it cannot be passed by easing the measure to fit
    what was built.

- Is a gap in Goal achieved when found during the work told to the user?

    Untold, the user finds it in use. Told, they decide it before approving.

## What did not change

- Does everything that worked before still work?

    What breaks, the user finds in use and has to fix.

## What was added

- Is nothing added that the goal does not need?

    A change the goal does not need is one the user never approved, and finding and removing it falls
    to them.

- Does the whole change follow the Rules in `steering.md`?

    Each task can follow them while the whole does not. Where it does not, it is done again.

## The README and design document

- Do they say what was built?

    The next session starts from them. Where they differ from what was built, the next work starts
    from a wrong ground.
