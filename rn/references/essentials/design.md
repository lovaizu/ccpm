# Design

The design is the README and design document that `steering.md` names, as they will stand once the
goal is achieved. Its readers are the user, who approves it at the Design sign-off as what the
product should be and how it is built; the conductor, who plans the tasks by it; and the generators,
who build by it. Each part is there because the goal needs it, so each question asks whether a part
does its job for this goal. How well the documents read is `writ`'s to check.

## The README's benefits

- Does it say rightly what the user gets from the product once the goal is achieved?

    The user judges from the README what the product does for them. When it says otherwise, they
    receive something other than what they expected.

## The README's use

- Can the product, once the goal is achieved, be used as the README says?

    When it cannot, the user does not get the benefit, and has to find out how to use it alone.

## The design document's benefits and features

- Can each line of Goal achieved when be traced to the features that make it hold?

    A line traced to no feature is never built. Traced, the user can tell before anything is built
    that the goal will be achieved.

## The conditions the design document keeps

- Do the conditions it keeps still hold after this change?

    When one breaks, something that served the user stops working, and the user finds out in use.

## How each feature is built

- Can a generator build it without deciding anything that is the user's to decide?

    What the design leaves open, a generator decides on the spot, and the product is built a way the
    user never chose.

## The ways chosen

- Does it say what the user decided, and what the ways not chosen would lose?

    Without the reason, whoever changes it later undoes the decision unaware, and pays again what was
    paid to make it.

## How it is checked

- Does each line of Goal achieved when have a scene where it is checked on the real thing, and what
  passes?

    Set before anything is built, it judges the deliverable by the same measure. Set after, it is
    drawn from what was built.

- Does each check fail when the goal is missed?

    A check that passes when the goal is missed proves nothing, and the user approves work that
    misses the goal.
