# The architecture stage of /rn:up

Step 10 of `/rn:up`, from the ux approved, or passed, to the architecture sign-off, taken as
`orchestrator.md` says.

10. Make the documents of how the work is built and checked, with the research they rest on, and
    stop at the architecture sign-off, so the user approves how the work will meet the goal, and
    how heavily each part of it is checked, before it is built.
    - In: the ux approved, or passed with no document, the stage architecture.
    - Hear which documents of how the work is built and checked it needs, such as an architecture,
      and the research each rests on: step 2 on work `plan`, each document a point of its own as
      the Role says, its kind `architecture` or the user's own. Where the user decides the work
      needs none, run `rn.py state --stage build --message <m>`, which sets Next step 11, and go
      on to step 11, as no architecture sign-off is needed.
    - Write the plan again, step 3 on work `plan`, giving nothing more, with a task for each
      document made, each research it rests on made before it.
    - Carry out each task in order, step 4; once the steering holds no task, step 5 on the
      architecture sign-off.
    - Out: the architecture sign-off waiting.
