# The ux stage of /rn:up

Step 9 of `/rn:up`, from the goal approved to the ux sign-off, taken as `orchestrator.md` says.

9. Make the documents of what the user gets and how they use it, and stop at the ux sign-off, so
   the user approves what the work gives them before how it is built is drawn on it.
   - In: the goal approved, the stage ux.
   - Hear which documents of what the user gets and how they use it the work needs, such as a UX
     and a README, in the order their checklists draw them, UX, then README: step 2 on work
     `plan`, each document a point of its own as the Role says, its kind `ux`, `readme` or the
     user's own. Where the user decides the work needs none, run `rn.py state --stage
     architecture --message <m>`, which sets Next step 10, and go on to step 10, as no ux sign-off
     is needed.
   - Write the plan again, step 3 on work `plan`, giving nothing more, with a task for each
     document made.
   - Carry out each task in order, step 4; once the steering holds no task, step 5 on the ux
     sign-off.
   - Out: the ux sign-off waiting.
