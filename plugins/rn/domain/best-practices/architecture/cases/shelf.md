# Shelf, a pass on every question

[The shelf architecture](../examples/shelf.md), a command on one computer that keeps a reading list
in a file and asks one service outside. It's a kept case of the [architecture best
practice](../best-practice.md): a deliverable with the verdict on each question that someone who
knows the developer's work gives, so that an evaluator proves itself on it before anyone trusts its
verdicts. It's also one of the best practice's examples, so this file holds its verdicts alone.

## Verdicts

| Question | Verdict | Why |
| --- | --- | --- |
| Q1 | yes | Two use cases carry the README's steps, and four ranked scenarios each end in a measure someone can check, such as 1,000 runs stopped at random. `D1` to `D3` each name the scenarios they answer. |
| Q2 | yes | Context, containers, and the components of the one container that holds four decisions, each with its type, its technology, its responsibility, and its file. |
| Q3 | yes | Every dependency points to list rules, Store and Catalog are its ports with a real adapter and a test's each, and `tests/test_imports.py` checks the rule. |
| Q4 | yes | Each relation between containers, and with Open Library, names what crosses, its form, its owner, and its contract. The concept model names the three data that every view uses. |
| Q5 | yes | `U1` draws each branch: a book number that isn't valid, one already on the list, none found, and the catalog unreachable. `U2` runs straight through three components, and one sentence gives its path. |
| Q6 | yes | The reader's computer and CI, with the Python each gives, and how a developer and a reader each start. |
| Q7 | yes | The opening gives the idea, the one principle carries its why, and each record gives its context, the option it beat, and its consequences. |
| Q8 | yes | No line says how a component works inside. The 5 seconds of `QA4` is a driver's measure, and a change to the list's fields, which `shelf/list.schema.json` holds, leaves every line true. |
| Q9 | yes | Each level checks against one thing, the doubles stand at the two ports, a weekly contract test keeps the catalog's double true, and the integration level takes each path once. |
| Q10 | yes | Each path of `U1` and the one of `U2` has its integration test, named before any code. |
| Q11 | yes | A new developer can follow `U1` from its driver through every section, and each element and data keeps its name across the figures, the tables, and the tests. |
