# Trial

A trial result is a file in the session's folder `.rn/<yyyymmdd>-<slug>/`, where rn keeps one piece
of work. It tells of a small try of a way before anything is built on it. It is used by the user
deciding a point it bears on, and by the maker of each later task's result it is handed to by name,
to tell whether that way works before they rest their decision or their work on it.

A trial result serves them by what was run and what came out, as it came out: the way tried, the
check that says whether it works, set before the run, and the result against that check. What was
run is told so that another can run it again. What the try did not cover is said, so the reader
knows how far the result holds. A trial result has no set shape beyond this, so this checklist has
no Format.

## Questions

### Q-1: Whether the way works

From the opening, can the reader tell which way was tried, for which point or work, and whether it
passed its check?

Why: the user decides and the maker builds on the verdict, so a verdict they must draw from the
output is drawn by each their own way.

### Q-2: A check set before the run

Is the check a pass or a fail on what the output shows, set before the run?

Why: a check fitted to the output, or one such as "runs well", is a reading of the output that
another would read otherwise.

### Q-3: Run again by another

Can another run the trial again from what it says alone, and get what it shows?

Why: a trial no one can run again is believed or doubted on the word of whoever ran it, and a result
that changes with a version shows the change only when someone runs it again. So the trial names
each version, setting and input, gives each step as it was run, and gives the output as it came out.

### Q-4: How far the result holds

Can the reader tell how far the result holds: the cases the trial did not cover, such as a larger
size or another platform, and each failure or work-around met on the way?

Why: a way tried on less than it is built for fails where it was not tried, and a failure or a
work-around left out is met again by the maker who builds on the way.
