# What rn's checklist for a fix rests on

`rn/checklists/fix.md` is drawn from 116 fixes and proposals of this branch's 30 sessions
(2026-10-20 to 24) that were later shown wrong in direction: by the user, a revert or redo, a new
fault, or the assistant's own later reading. Each was read from the session's own words and git.

## What went missing, and its item

- The cause (B-1): a fix fitted to the one case a run showed, while the rule it broke named more,
  such as the run's own files left out of what the first user is given and the CCS not, a guard
  widened one bypass at a time, the time of a run fixed while its behaviour stayed, the prompts
  shortened while the checklist that made them long stayed.
- The purpose (B-2): a fix made to the form of a checklist item, a count or a passing run, such as
  turn's design split to the item's form into a spec, an exception written for a principle the
  purpose gives no need for, perfect blocking chosen for a minor risk branch protection already
  guards.
- The place and the amount (B-3): every decision of a talk or a trial added to the design, a
  sentence added to three prompts for each trial fault, a phrase naming the one failure beside the
  line that says the rule.
- The whole (B-4): lane's architecture saying "a tool call" while its README's Lanes watch how a
  subagent ends, in_form's new read stopped by read_only on the same step, a table moved without its
  column, a README changed ahead of the code.

## What is held elsewhere

- Keeping what the user approved: turn's generator makes the work from the CCS and the files it
  names alone, and an agreed document changes only with the user, by rn's sign-offs and
  `.claude/rules/final-check.md`; `checklist.md` B-4 takes no item asking whether a work matches
  what was decided.
- Tracing on paper before a run and trying one small first: steps of the work, which `checklist.md`
  B-3 gives to the plan's tasks; `session/plan.md` holds them in each task's steps 3 and 4.

## How it reaches turn

- rn's CCS names it under `constraints` on every call, `{"fix": "<rn>/checklists/fix.md"}`, since a
  fix happens inside every run: each send-back and each later round changes the generator's own work,
  a new work's too. turn gives the generator every file the CCS names and the first user none of
  them but those the receiver has, and judges only the checklists' items; so turn is unchanged, as
  its architecture defines nothing of the CCS but the kinds the call names.
- Not yet tried in a run: whether the generator holds it on a send-back shows in rn's trials (T8,
  T14).
